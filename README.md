# 우리집 자산 대시보드 (Asset Dashboard)

부부가 함께 쓰는 **로컬 우선** 자산관리 · 가계부 웹앱입니다.
매달 번 돈과 쓴 돈을 구성원(남편/아내)별로 기록하고, 순자산이 어떻게
쌓이는지 그래프로 확인합니다.

**접속 주소**: https://ryu1127.github.io/asset-dashboard-private/
(북마크해두고 쓰세요. 데이터는 서버가 아니라 접속한 기기의 브라우저에만
저장됩니다 — 자세한 원리는 [프라이버시](#프라이버시--데이터는-어디에-저장되나) 참고)

## 특징

- 🖥️ **로컬 우선** — 회원가입 없이 브라우저에서 바로 사용. 데이터는 그 브라우저
  (IndexedDB)에만 영구 저장되고, 외부 서버로 전송되지 않습니다.
- 👫 **구성원 구분** — 모든 수입/지출을 남편·아내로 구분해 입력하고,
  각각 또는 합산으로 조회.
- 🏷️ **계층형 카테고리** — 「급여」 아래 「월급」·「상여/보너스」처럼 상위/하위
  카테고리로 세분화. 기존 카테고리를 다른 상위로 옮겨도 거래 내역·예산·적요
  규칙이 그대로 유지됩니다.
- 📊 **대시보드 그래프** — 이번 달 수입/지출/저축률, 최근 6개월 추이,
  카테고리별 지출, 구성원별 비교, 누적 저축 추이.
- 🎯 **예산 관리** — 카테고리별 월 예산을 정하고 소진율을 진행 바로 확인.
  하위 카테고리가 있는 카테고리는 하위 예산의 합으로 자동 계산됩니다.
- 💰 **자산 현황** — 월별 계좌 잔액을 입력해 순자산 추이 기록. 부채(대출 등)는
  자동으로 총자산에서 차감되어 순자산에 반영됩니다.
- 🔁 **반복 거래** — 월급·구독료처럼 매월 반복되는 항목을 등록하면 앱을 열 때
  밀린 달까지 자동으로 기록(중복 없음).
- 📥 **CSV 가져오기** — 은행·카드사 CSV를 불러와 거래로 일괄 등록.
- 🔎 **적요 자동 분류** — 거래 내용(적요) 키워드로 카테고리 자동 배정(예: 스타벅스
  → 식비). 카테고리별로 어떤 키워드가 연결되어 있는지 한눈에 보고 관리.
- ☁️ **구글 드라이브 백업** — 버튼 한 번으로 내 구글 드라이브에 백업하고 다른
  기기에서 불러오기. 마지막 저장 시각이 표시되어 깜빡 잊기 어렵습니다.
- 💾 **JSON 백업** — 내보내기/가져오기로 로컬 파일 백업.

## 처음 시작하기

이 순서대로 한 번만 세팅하면 그다음부터는 자산 현황만 매달 업데이트해도
충분합니다.

### 1. 구성원 확인

「설정 · 백업」 → 👫 구성원에서 기본값 「남편」·「아내」를 실제 이름으로
바꾸고 싶으면 이름 칸을 클릭해 수정하세요 (색상도 옆에서 바꿀 수 있어요).

### 2. 계좌 만들기

「설정 · 백업」 → 🏦 계좌 / 자산 계정에서 실제로 갖고 있는 계좌·자산·부채를
하나씩 등록합니다.

- 이름: 자유롭게 (예: "국민은행 급여통장", "카카오뱅크 적금")
- 유형: **현금 · 예금 · 적금 · 투자 · 부동산 · 부채** 중 선택
- 소유: 남편 / 아내 / 공동

> 💡 대출·카드론처럼 **빚진 것**은 유형을 반드시 「부채」로 선택하세요. 나머지
> 유형(현금~부동산)은 전부 "내가 가진 것"으로 자산 합산에 더해지고, 「부채」만
> 자동으로 차감됩니다.

### 3. 카테고리 정리 (선택)

기본 카테고리(식비, 교통, 급여 등)가 이미 들어있어 바로 써도 되지만, 더
세분화하고 싶으면 「설정 · 백업」 → 🏷️ 분류 카테고리에서:

- 각 카테고리 아래 **"+ 하위 카테고리"** 입력창으로 세부 항목 추가
  (예: 「식비」 아래 「외식」·「장보기」·「배달」)
- 이미 있는 카테고리를 다른 상위로 옮기고 싶으면, 그 카테고리 옆 **"이동"**을
  눌러 상위를 선택 — 지금까지 쌓인 거래 내역·예산·적요 규칙은 그대로
  유지됩니다 (아무것도 안 끊깁니다)

### 4. 이번 달 자산 잔액 입력 — 가장 중요한 단계

「자산 현황」 메뉴에서 계좌별로 **지금 잔액**을 입력하고 저장 버튼을
누르세요.

- 자산(현금·예금·적금·투자·부동산): 그대로 잔액 입력 (예: `10,000,000`)
- 부채(대출·카드론 등): **빚진 금액을 양수로 그대로 입력** (예: 500만원 남았으면
  `5,000,000`). 마이너스 부호는 필요 없고, 화면에 빨간색으로 자동 표시되며
  순자산 계산 시 자동으로 빠집니다.

매달 말 다시 이 화면에 와서 그때 잔액으로 고쳐 입력하면, 위쪽 그래프에
순자산 추이가 쌓입니다. **이것만 매달 해도 자산 흐름 파악에는 충분해요.**

### 5. (선택) 거래를 상세히 기록하고 싶다면

「거래 입력」에서 날짜·금액·구성원·분류를 골라 건별로 기록할 수 있어요.
매번 입력이 번거로우면:

- **반복 거래**: 월급·구독료처럼 매달 같은 항목은 한 번만 등록해두면 자동 기록
- **CSV 가져오기**: 은행 앱에서 내려받은 거래내역 CSV를 통째로 불러와 일괄 등록
- **적요 자동 분류**: CSV로 가져올 때 "스타벅스"가 들어간 내용은 자동으로
  "식비"로 분류되도록 키워드 규칙을 걸어두면 편해요 (「설정」 하단)

### 6. 예산 걸기 (선택)

「예산」에서 지출 카테고리별로 월 한도를 입력하면 소진율이 진행 바로
보여요. 하위 카테고리가 있는 카테고리(예: 식비)는 직접 입력하는 대신
하위 항목(외식+장보기+…) 예산의 합으로 자동 계산됩니다.

### 7. 구글 드라이브에 백업해두기

「설정 · 백업」 → ☁️ 구글 드라이브 동기화에서 "구글 계정 연결" 후
"드라이브에 저장"을 눌러두면, 다른 기기(폰 등)에서 같은 구글 계정으로
"드라이브에서 불러오기" 해서 데이터를 이어갈 수 있어요. 실시간 동기화는
아니라서, 저장한 지 3일이 넘으면 화면에 빨간 글씨로 알려줍니다.

## 프라이버시 — 데이터는 어디에 저장되나

이 사이트(https://ryu1127.github.io/asset-dashboard-private/) 자체는
**빈 앱 껍데기**만 배포되어 있고, 실제 입력한 자산·거래 데이터는 오직
**그 브라우저의 로컬 저장소(IndexedDB)**에만 있습니다.

- 다른 사람이 같은 주소로 들어와도 빈 화면만 보이고, 내 데이터는 절대
  보이지 않습니다.
- 같은 기기·같은 브라우저에서만 데이터가 유지됩니다. 폰과 PC는 데이터가
  따로 쌓이므로, 여러 기기에서 쓰려면 위의 "구글 드라이브 백업"으로
  수동 동기화하세요.
- 구글 드라이브에 저장할 때도 `drive.file` 권한만 사용해 **이 앱이 만든
  파일만** 접근하며, 본인 드라이브의 다른 파일은 절대 건드리지 않습니다.

## 로컬에서 직접 실행하기 (개발자용)

Node.js 18+ 가 필요합니다.

```bash
npm install      # 최초 1회
npm run dev      # 개발 서버 실행 → 자동으로 브라우저 열림 (http://localhost:5173)
```

### 프로덕션 빌드

```bash
npm run build    # dist/ 폴더 생성
npm run preview  # 빌드 결과 미리보기
```

### 배포

`main` 브랜치가 아니라 `claude/asset-management-app-design-wp1tn1` 브랜치에
푸시하면 `.github/workflows/deploy.yml`이 자동으로 빌드해서 GitHub Pages에
배포합니다.

## 설계 개요

### 핵심 개념: 현금 흐름 ↔ 자산 잔액 분리

- **현금 흐름 (거래 입력)** — 언제/누가/얼마를 벌고 썼는지의 개별 내역.
- **자산 잔액 (자산 현황)** — 매월 말 계좌별 잔고 스냅샷. 투자 평가액은
  거래 없이도 오르내리므로, 순자산 추이는 이 스냅샷으로 그립니다.

### 데이터 모델

| 테이블 | 필드 |
|--------|------|
| `members` | name, color |
| `categories` | name, kind(수입/지출), color, parentId(상위 카테고리) |
| `accounts` | name, type(현금/예금/적금/투자/부동산/부채), owner |
| `transactions` | date, kind, amount, memberId, categoryId, accountId, memo |
| `snapshots` | month, accountId, balance |
| `budgets` | categoryId, amount(월 예산 한도) |
| `recurring` | memo, kind, amount, memberId, categoryId, dayOfMonth, startMonth, active, lastPostedMonth |
| `catRules` | keyword, categoryId (적요 키워드 자동 분류) |

### 기술 스택

- **Vite + React + TypeScript** — 가벼운 SPA
- **Dexie (IndexedDB)** — 브라우저 로컬 DB, 네이티브 모듈 불필요
- **Recharts** — 차트
- **react-router-dom** (HashRouter) — 페이지 라우팅
- **Google Identity Services + Drive API** — 클라이언트 사이드 전용 구글
  드라이브 백업 (서버·클라이언트 시크릿 불필요, `drive.file` 스코프)

## 클라우드 실시간 동기화 (지금은 미적용)

지금 있는 "구글 드라이브 백업"은 **수동 · 전체 파일 덮어쓰기** 방식이라
실시간 동기화는 아닙니다. 여러 기기에서 동시에 입력하는 일이 잦아지고,
자산 데이터가 상시 외부 서버에 있는 것을 받아들일 수 있다면 아래 옵션을
검토할 시점입니다.

- **Dexie Cloud** — 지금 Dexie 코드를 거의 그대로 두고 동기화만 얹음. 오프라인
  유지, 부부 2명은 무료권. **변경 최소**.
- **Supabase** — Postgres + 인증 + 권한규칙(RLS) + 실시간. 데이터 계층을 교체하고
  로그인 화면을 추가해야 하지만 **완전한 제어·확장성**.

> 어느 쪽이든 현재 스키마와 백업 JSON 구조를 그대로 이어받도록 설계되어 있어,
> 그동안 쌓인 데이터를 잃지 않고 옮길 수 있습니다.
